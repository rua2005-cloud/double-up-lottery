# ST:REDRIVE 01 — 設定1 STスロットシミュレータ

実機の公開されたフローを参考に作った、**独自の仮想コインゲーム**です。実機の権利物（画像・音・ロゴ・キャラクター）は使用していません。現金・景品との交換機能はありません。

## 起動方法

`index.html` をローカルWebサーバー上で開いてください（JavaScriptのES Modulesを使用するため、`file://` 直開きでは動かない環境があります）。

```bash
cd slot-simulator
python3 -m http.server 8000
# http://localhost:8000/
```

GitHub Pagesで本リポジトリの`main`/ルートを公開している場合は、`/slot-simulator/` から遊べます。

## 操作方法

- **1G 回す**：1物理ゲーム進める。キーボードのスペースでも可能。
- **オート開始**：選択速度（4/50/500/8000G/秒）で消化。
- **高速オート**：速度選択にかかわらず最大8,000G/秒で消化。
- **停止条件**：1,000/10,000/50,000G、AT当選、ボーナス当選、上位AT突入、手動停止から選択。
- **停止**：途中で安全に中断。状態・累積差枚・機械割を保存。
- **データリセット**：新しい乱数で設定1を最初から開始。

集計は通常時・CZ・HOLD・AT・ボーナスを含む**物理ゲーム1回につき3枚BET**、ボーナスの表示枚数は総払出として計算。AT/CZ確率の分母は通常時消化ゲーム数。localStorage に進捗を保存します。

## 内部フロー

- 通常時：成立役・100/250/400/600/750GのCZゾーン・スタンプ・AT/CZ天井。
- CZ：通常53%、高期待度83%、8G。
- AT：導入のプロローグ100枚（総払出）→初回20G（ボーナス突破期待約60%）。
- 通常AT：前半50G（ボーナスで残りG引き継ぎ）→後半10GのST（ボーナスで10G再セット）。
- ポイント1000pt：前半なら50Gを完走してから上位CZ、後半ならボーナス終了直後に上位CZ。
- 上位CZ：10G、期待度約70%。成功でチェリー・スイカ両方Lv2の上位AT。
- 上位AT：1000pt達成時の50G再セット・終了後100G引き戻し。
- 変換HOLD：追加2〜4物理ゲーム、ST残りゲーム数は減らさない。

一部は独自確率であり、実機の未公表抽選の再現を保証しません。公開資料を参考にしたモデルの数値です。

## 機械割・テスト

目標：設定1の**97.9%**。ブラウザ用JS版では4種の乱数シードで各2,000万物理G（計8,000万G）の計算を実施し、機械割は**約97.83%**でした。これは有限試行の推定値です。実際の結果は試行回数でぶれます。

```bash
cd slot-simulator
npm test
node simulation-check.js 1000000 42
```

Node.js 20以上推奨。依存パッケージ不要。`engine.test.js` で状態遷移、引き戻し100G目、HOLD、総払出、セーブ復元、高速オートと単発消化の同値性などをテスト。

## 設計上の補足

元のPython v2.1設計との統計的な差を調整するため、ブラウザ版の通常AT・200枚ボーナスの抽選比率は **49.9%** にしています。他の主要な数値は`engine.js`の`CONFIG`にまとまっています。この独自調整値は実機メーカーの内部値ではありません。
